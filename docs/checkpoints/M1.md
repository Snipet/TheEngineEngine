# M1, step 2: TheEngineEngine in its own window

*For a person on Windows and on macOS. Step 1 (FunkGui's gallery alone, nothing of ours in it) is card A's page;
this is step 2 of [checkpoints.md](../plan/checkpoints.md): the reference engine, compiled when the application
starts, heard through the default audio device, driven from the keyboard.*

**What has been done, and by whom** (2026-11-24, kept up to date at the end of this page: "Results so far").
In cloud containers and on CI's runners, with no real GPU and no sound card: the application builds on Windows,
macOS and Linux, opens its window (Direct3D 11, Metal, Vulkan), compiles the engine, starts and revs it from
scripted keys, and reads a frame back. On a person's machine: Windows, once, as far as `--info` and
`--engine tone`. Whether it sounds right, on any system, nobody has said yet: every answer below is news.

## 1. Get it

On GitHub: the repository, **Actions**, the workflow **Build**, the newest run of the branch
`claude/awesome-gates-ntdb58` whose **windows-x64** (or **macos-arm64**) job is green down to *Upload the
application*; at the bottom of the run's page, **Artifacts**:

| Artifact | What is in it |
|---|---|
| `TheEngineEngine-windows-x64` | a folder: `TheEngineEngine.exe`, `tee-headless.exe`, `sim/`, `content/`, `licences/`, the Visual C++ runtime's DLLs, `README.txt` |
| `TheEngineEngine-macos-arm64` | `TheEngineEngine-macos-arm64.tar.gz`: a folder with `TheEngineEngine.app`, `tee-headless`, `licences/`, `README.txt` |
| `TheEngineEngine-listen-<platform>` | no program: the engine started, revved and stopped, rendered by the same code on the CI machine, as a WAV file, with pictures. Listen to this if the application will not run |

(From a terminal: `gh run list --branch claude/awesome-gates-ntdb58 --workflow Build`, then
`gh run download <run id> --name TheEngineEngine-macos-arm64`.)

## 2. Run it

**Windows.** Unzip the artifact. Double-click `TheEngineEngine.exe`, or better, from a Command Prompt or PowerShell
in that folder:

    .\TheEngineEngine.exe --info
    .\TheEngineEngine.exe

A console window opens beside the application's own and says what it found: it is a console program for now, on
purpose. Windows may say the file is from an unknown publisher (it is not signed): *More info*, *Run anyway*.

**macOS** (Apple silicon). In Terminal, where the download landed:

    tar -xzf TheEngineEngine-macos-arm64.tar.gz
    cd TheEngineEngine-macos-arm64
    xattr -dr com.apple.quarantine TheEngineEngine.app tee-headless
    ./TheEngineEngine.app/Contents/MacOS/TheEngineEngine --info
    open TheEngineEngine.app

The `xattr` line is for the quarantine mark a download carries: the application is signed ad hoc (no Apple
developer identity), and without that line macOS refuses it as "damaged" or "from an unidentified developer". If
you unpacked with `tar` in Terminal as above the mark may not be there at all, and the line then does nothing: say
which it was. Started with `open` (or a double click) it prints nowhere; started as
`./TheEngineEngine.app/Contents/MacOS/TheEngineEngine` it prints in the Terminal, which is what the questions below
ask for.

**Or build it from a clone**, on a Mac whose FMinus checkout has already built its LLVM (so nothing here builds
LLVM): CMake 3.30 or newer and Ninja, then

    cmake --preset release -DTEE_BUILD_APP=ON -DTEE_DEPS_DIR=<your FMinus checkout>/.deps
    cmake --build --preset release --target TheEngineEngine
    ./build-release/bin/TheEngineEngine.app/Contents/MacOS/TheEngineEngine --info

(`FMINUS_DEPS_DIR=<your FMinus checkout>/.deps` in the environment serves as well as `-DTEE_DEPS_DIR`.) The first
build compiles bgfx's shader compiler, which is the slow part: about 2,000 CPU-seconds, once.

## 3. What to press

| | |
|---|---|
| Return | the start key: press it and the engine cranks and starts; hold it a second and it switches off |
| Up, or W | the throttle (it eases down while held) |
| Down, or S | the brake |
| E / Q | a gear up / down (the gearbox works its own clutch, and pulls away by itself in first) |
| N; 1 to 6 | neutral; that gear |
| the mouse | the panel's START button, its throttle strip, its dials and menus |

It starts in a car, in neutral. So: **Return**, wait for the idle, **hold W** to rev it to its limiter, let go.
Then **E** for first gear and **W** to pull away. [controls.md](../controls.md) has the rest.

**Which engine, which panel.** The artifact you may already have (run 45399202005) opens the *reference* engine in
its own panel: the dashboard the ten checks below describe. Artifacts built later open the *simulator*
(`sim/engine.fm`, the reference under its new contract) in the application's *frame*, a rail of workspaces with
pages of controls, which is being built today; in those, `--ref-panel` opens what the checks describe. The sound
should be the same either way: say if it is not.

If the instruments look wrong but you want to hear the engine: `--panel plain` shows a plain panel of numbers and
dials that needs no shader. If nothing is heard: `--engine tone` plays a plain tone with no simulator behind it,
which tells a silent audio device from a simulator that did not start.

## 4. Ten things to look at and listen for

Each a yes or a no, and a sentence where it is a no.

1. **It opens.** A window appears with the engine's panel: a header, a dashboard with two round dials and a drawing
   of the engine from above, pages of knobs, and a strip at the bottom with START, a throttle bar and the gear. How
   many seconds from launch to the window? (The engine is compiled first: the console says "compiled in ... s".)
2. **It is sharp.** Text and lines are crisp at the screen's own density (a Retina display, or Windows at 150 %),
   not blurred or doubled; the window is the size you would expect, not tiny or huge.
3. **Return starts it.** You hear the starter crank, then the engine catch and settle to an idle. The rev counter
   rises to an idle speed, and the header's STATE is no longer OFF.
4. **W revs it.** Holding W (or Up) raises the revs smoothly to the limiter and holds there, rattling against it;
   letting go, they fall back to the idle. The throttle bar follows the key.
5. **The sound is whole.** No crackle, dropout, stutter or buzz, at idle and at the limiter, for a minute. Does it
   sound like the engine you know from the plugin? (Nobody here has heard it: say what you hear.)
6. **The picture keeps up.** The needles and the engine's drawing move smoothly while it runs; no tearing; dragging
   the window's edge does not freeze the sound.
7. **A dial changes the sound.** On the ENGINE page turn SIZE, or pick another LAYOUT: the sound follows (a layout
   under a short fade), and the header and the drawing with it.
8. **It drives.** E puts it in first (the gear shows 1); W pulls the car away, the speedometer rises; E again
   shifts up with a short cut; S brakes; N returns to neutral without a stall.
9. **It stops.** Holding Return for a second switches the engine off: the sound runs down and the counter falls to
   zero. Closing the window ends the sound at once, and the program exits (on Windows the console closes or
   returns to its prompt; on macOS the Terminal's prompt comes back).
10. **It idles quietly.** With the engine off, the application's own CPU use is low (Task Manager, Activity
    Monitor: a few percent, not a whole core); with the engine running, say what it reads.

## 5. What to send back

- The ten answers.
- The whole output of `--info`. It says the renderer (Direct3D 11 on Windows, Metal on macOS, are what is
  expected), the window's size and scale, the audio driver, device, rate and buffer, and how long the compile took.
  The buffer it prints is the device's buffer as SDL reports it: the least the output latency can be, not a
  measurement of it. If the sound feels late against the keys, say so: that is why the audio device sits behind a
  seam.
- What the console printed, if anything looked like an error.
- A screenshot of anything odd.
- On macOS: whether the `xattr` line was needed, and whether a dialog asked for anything.

## 6. If it does not run

| What happens | What it probably is | What to try |
|---|---|---|
| "The window did not open" in the console, with a reason | the GPU layer | send the reason; nothing to try |
| The window opens, the dashboard areas are striped boxes or empty | the panel's shaders | `--panel plain` (and send a screenshot of the first) |
| The window is fine, there is no sound | the audio device, or the engine | `--info` (the audio line); then `--engine tone`: a tone that plays means the device is fine |
| The panel is a plain one with red text and compiler messages | the simulator did not compile | send the text; it is FMinus's own message |
| macOS says the application is damaged | the quarantine mark | the `xattr` line above |
| Windows says a DLL is missing | the C runtime | say which DLL; the folder should carry them |

In every case the `TheEngineEngine-listen-<platform>` artifact has the engine's sound as a WAV file rendered by
the same code, so there is something to listen to today.

## Results so far

**CI's runners, no person** (run 45399202005 and later; pictures and a WAV in `TheEngineEngine-listen-<platform>`).
The same on all three: the window opens, the reference compiles (1.3 to 1.9 s), Return starts it and W revs it to
about 6,350 rpm, a frame is read back from the GPU, and `tee-headless` renders the same 14 seconds (peak 0.84318,
rms 0.11550 on each).
- Linux (Xvfb, Mesa's software Vulkan, SDL's dummy audio): the whole panel draws.
- macOS (Metal in the runner's virtual machine; CoreAudio's virtual device, 48,000 Hz, 256 frames): the whole panel
  draws; `codesign --verify` passes on the bundle.
- Windows (Direct3D 11 on the runner; no audio device, so SDL's dummy driver): the dials, needles, seven-segment
  numbers and the spectrum draw; `header.sc` is refused ("the shader reads the uniform ORANGE") and the words drawn
  with the shaders' own dot font are missing (RPM, MPH, CAR, START, FIRING ORDER). Both are the interface's
  shaders under Direct3D 11.

**Windows, a person's machine** (the artifact of run 45399202005; a 3840 x 2160 display at 150 %):
- `--info`: the engine compiled in 2.11 s; `wasapi: Speakers, 48000 Hz, buffer 480 frames (10.0 ms)`; renderer
  Direct3D 11; the window 840 x 764 logical px, 1260 x 1146 pixels, scale 1.5.
- `--engine tone`: 789 frames at 60.0 a second, 1,381 audio callbacks, the largest request 480 frames, and a clean
  exit (`tee-app: ok`).
- Printed: the one known complaint, `ref/header.sc` refused because it reads the uniform ORANGE (known; that panel
  is being retired from the application, docs/plan/ui-design.md section 1).
- The machine had no audio at the time: the tone played to a device nobody heard. **Nothing has been heard yet**, on
  any system: not the tone, not the engine. The ten checks above are still to be answered.

**macOS, a person's machine**: not run by a person yet (planned for the afternoon of 2026-11-24).
